## 2. The Core Problem

### Why TrueArch Exists

Current AI-native software engineering is fundamentally broken at the architecture layer:

| Problem | Impact |
|---|---|
| **Duplicated Reasoning** | Every coding session re-discovers architecture from partial ignorance |
| **Framework Churn** | Ecosystem changes faster than docs, tutorials, and recommendations can keep up |
| **Architecture Uncertainty** | Developers don't know which stack is battle-tested vs. hyped vs. dying |
| **Stateless AI Systems** | Coding agents have no persistent architectural memory across sessions |
| **Token Inefficiency** | Agents waste context re-computing decisions that should already be known |
| **Hallucinated Recommendations** | LLMs recommend deprecated, incompatible, or unsafe frameworks |
| **No Production Intelligence** | No system tracks what actually *works* in production vs. what breaks |

### Root Cause

> Current AI systems are **stateless and isolated**. They repeatedly recompute architectural intelligence independently — creating ecosystem-wide redundancy, inconsistency, and costly architectural mistakes.

### The Missing Layer

**Persistent, adaptive, continuously evolving architecture intelligence** — a layer that knows not just the documentation, but the *outcomes*.

## 8. Integration Philosophy

> **Core Principle: Users should NEVER leave their workflow.**

| ❌ Wrong Approach | ✅ Right Approach |
|---|---|
| Dashboard-first | Invisible integration first |
| Manual prompting | Proactive intelligence injection |
| External search | Contextual injection at decision moment |
| Standalone tool | Headless intelligence APIs |

### Integration Priority Order

1. **MCP Server** — Universal protocol for agent-tool interaction
2. **REST API** — Core intelligence engine accessible to everything
3. **SDK** — Language-specific packages (Python, TypeScript first)
4. **Cursor Integration** — Highest-value IDE integration
5. **Claude Code / Codex / Copilot** — Ecosystem presence
6. **VS Code Extension** — Long-tail developer reach
7. **CLI** — Terminal-native developer workflow

### Why MCP Is Strategic

- Adopted by: OpenAI, Anthropic, Cursor, Replit, Sourcegraph
- Becoming the **universal protocol** for agent-tool interaction
- Maps perfectly to TrueArch's nature as a contextual intelligence provider
- BUT: MCP is only the **transport layer** — the moat is the intelligence, not the protocol

## 12. Cost Management Strategy

### Early-Stage Cost Discipline

**What NOT to do (GPU-burn death):**
- Continuously crawl the entire internet
- Continuously embed everything
- Run large inference pipelines constantly
- Build autonomous agents everywhere

**What TO do:**

| Strategy | Rationale |
|---|---|
| **Curated Intelligence First** | Manually curate top frameworks, releases, benchmarks — high quality, low cost |
| **Small Models for Most Tasks** | Reserve frontier models only for complex tradeoff reasoning |
| **Aggressive Caching** | Architecture outputs, comparisons, recommendations — cache everything |
| **API-First, Infra-Lean** | Headless intelligence avoids expensive hosting/compute |

> **Core principle:** Repeated reasoning should NOT happen repeatedly — internally OR externally.

## 13. Core Product Principles

These principles define TrueArch's DNA. Every product decision should be evaluated against them.

1. **Intelligence should reduce unnecessary reasoning** — don't re-compute what's already known
2. **Users should never leave their workflow** — embed intelligence where work happens
3. **Architecture decisions must be outcome-driven** — not documentation-driven
4. **Recommendations must be continuously adaptive** — stale is dangerous
5. **Neutrality builds trust** — never bias toward any LLM, framework, or vendor
6. **Infrastructure compounds more than tools** — build for long-term leverage
7. **Production reliability > novelty** — battle-tested beats cutting-edge
8. **Proactive intelligence > reactive search** — appear before the question is asked
9. **Context compression > context flooding** — inject only what matters
10. **Data network effects > feature advantages** — moat through learning, not building

## 17. Decision Logs

> Record every major strategic decision here with rationale and alternatives rejected.

### DL-001 | Product Category Name
- **Decision:** "Decision Infrastructure" (not "AI tool" or "coding assistant")
- **Rationale:** Tools get replaced. Infrastructure compounds. Category name affects valuation, moat, defensibility, and investor perception.
- **Alternatives Rejected:** "AI coding tool", "architecture advisor", "developer assistant"
- **Date:** 2026-05-16

### DL-002 | Company Name — TrueArch
- **Decision:** TrueArch
- **Rationale:** "Arch" signals infrastructure/architecture. "True" signals validated/trustworthy intelligence. Short, memorable, enterprise-compatible, expandable.
- **Concerns:** "Arch" is somewhat common; domain/trademark must be verified.
- **Alternatives Rejected:** Generic AI-named alternatives
- **Action Required:** Verify truearch.ai / truearch.dev domain and trademark availability
- **Date:** 2026-05-16

### DL-003 | Primary Integration Layer
- **Decision:** MCP Server as primary integration, REST API as core
- **Rationale:** MCP is becoming universal agent-tool protocol. Adopted by OpenAI, Anthropic, Cursor. Maps perfectly to contextual intelligence use case.
- **Critical Caveat:** MCP is transport only. Moat is the intelligence, not the protocol.
- **Date:** 2026-05-16

### DL-004 | Beachhead Market
- **Decision:** AI startups + AI agencies first
- **Rationale:** Maximum ecosystem pain, fastest adoption, easiest reach, lowest sales friction
- **Alternatives Rejected:** Enterprises (too slow), OpenAI/Anthropic (too hard), mass market (too broad)
- **Date:** 2026-05-16

### DL-005 | GTM Strategy
- **Decision:** Authority-first GTM (publish evaluations, benchmarks, reports — NOT ads)
- **Rationale:** Developers trust benchmark providers and evaluators. Becoming the neutral authority builds switching cost via trust, not features.
- **Date:** 2026-05-16
